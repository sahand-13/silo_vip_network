# Silo VIP Network

فارسی | [English](README.md)

سیلو وی‌آی‌پی نتورک پنل وبی برای مدیریت سرویس‌های مبتنی بر Xray و حساب‌های نمایندگی است. این پروژه فورکی از [3X-UI](https://github.com/MHSanaei/3x-ui) است که امکاناتی برای سلسله‌مراتب حساب‌ها، سهمیه نمایندگان، مالکیت کلاینت و پشتیبان تلگرام هر حساب دارد.

[نسخه‌ها](https://github.com/sahand-13/silo_vip_network/releases) · [گزارش مشکل](https://github.com/sahand-13/silo_vip_network/issues) · [راهنمای نصب سرور](docs/silo-server-install.fa.md)

## امکانات

- حساب‌های صاحب پنل، سودو، ادمین، ریسلر و Infinity با سطح دسترسی متناسب با نقش و مجوزهای اختصاص‌داده‌شده.
- تخصیص سهمیه تعداد کلاینت و حجم به حساب‌های زیرمجموعه؛ امکان تعیین تعداد کلاینت نامحدود از نظر ترافیک یا برداشتن محدودیت تعداد کلاینت، بر اساس سیاست حساب.
- مدیریت اینباندهای مجاز و کلاینت‌ها، شامل تنظیمات، حجم، انقضا، لینک اشتراک و QR. حساب Infinity می‌تواند کلاینت‌های زیرمجموعه‌های خود را نیز مدیریت کند.
- انتقال مالکیت کلاینت برای حساب‌های دارای مجوز. نحوه محاسبه سهمیه و بازگشت حجم باقی‌مانده به نوع عملیات و سیاست حساب وابسته است.
- تنظیم پشتیبان تلگرام مستقل برای حساب‌های زیرمجموعه و پشتیبانی اتصال بات تلگرام از طریق پروکسی یا اوتباند تنظیم‌شده.
- مدیریت اینباند، اوتباند، مسیریابی، آمار و اشتراک‌ها در رابط چندزبانه با تم روشن و تیره.
- استفاده از SQLite یا PostgreSQL، API، امکان مدیریت چند نود و نصب با Docker.

## نصب روی سرور لینوکس

در سروری که دسترسی root یا sudo دارد، نصب‌کننده همین مخزن را دانلود و اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/sahand-13/silo_vip_network/main/install.sh -o install-silo.sh
sudo bash install-silo.sh
```

نصب‌کننده فایل سازگار با معماری سرور را از آخرین نسخه پایدار دریافت می‌کند، در صورت وجود فایل checksum صحت آن را بررسی می‌کند و پنل را به‌صورت سرویس نصب می‌کند. تنظیمات خواسته‌شده را تکمیل کنید و نام کاربری، رمز و آدرس پنل تولیدشده یا انتخاب‌شده را در جای امن نگه دارید. پورت پنل و پورت اینباندهایی را که می‌سازید در فایروال سرور باز کنید.

برای نصب نسخه مشخص، تگ آن را وارد کنید:

```bash
sudo bash install-silo.sh v3.11.0
```

برای نسخه توسعه‌ای از `sudo bash install-silo.sh dev-latest` استفاده کنید؛ محتوای این نسخه ممکن است بین نصب‌ها تغییر کند. در نصب غیرتعاملی اطلاعات تولیدشده در `/etc/x-ui/install-result.env` ذخیره می‌شود؛ این فایل حاوی اطلاعات ورود است و باید از آن محافظت شود.

نسخه لینوکس فعلی شامل بسته‌های `amd64`، `arm64`، `386`، `armv5`، `armv6`، `armv7` و `s390x` است؛ وجود هر بسته در نسخه‌های بعدی به نتیجه ساخت همان نسخه بستگی دارد. اگر خطای 404 دریافت کردید، وجود فایل معماری سرور را در [صفحه نسخه‌ها](https://github.com/sahand-13/silo_vip_network/releases) بررسی کنید.

### مدیریت سرویس

```bash
sudo x-ui             # منوی مدیریت پنل
sudo x-ui status
sudo x-ui restart
sudo systemctl status x-ui
sudo journalctl -u x-ui -n 100 --no-pager
```

دستورهای `systemctl` و `journalctl` مربوط به سیستم‌های دارای systemd مانند اوبونتو هستند. به‌روزرسانی و سایر عملیات مدیریتی از منوی `x-ui` در دسترس است. قبل از تغییر نصب موجود، از دیتابیس و گواهی‌ها پشتیبان تهیه کنید.

## نصب با Docker

روی لینوکس، Docker Engine و افزونه Docker Compose را نصب کنید؛ سپس ایمیج همین مخزن را بسازید:

```bash
git clone https://github.com/sahand-13/silo_vip_network.git
cd silo_vip_network
sudo bash scripts/silo-server.sh install
```

این روش از `docker-compose.silo.yml`، شبکه میزبان لینوکس و volumeهای جداگانه برای دیتابیس و گواهی‌ها استفاده می‌کند. در اجرای اول، دستور مشاهده اطلاعات ورود در لاگ نمایش داده می‌شود. پورت پیش‌فرض پنل در این روش `2053` است.

```bash
sudo bash scripts/silo-server.sh status
sudo bash scripts/silo-server.sh logs
```

پس از دریافت کد نسخه دلخواه مخزن، با `sudo bash scripts/silo-server.sh update` کانتینر را دوباره بسازید و اجرا کنید. داده‌های نصب مستقیم و Docker جدا هستند و خودکار به یکدیگر منتقل نمی‌شوند.

## اجرای محیط توسعه

بک‌اند با Go و CGO و فرانت‌اند با React، TypeScript و Vite ساخته شده است. به نسخه Go مشخص‌شده در `go.mod`، نسخه Node.js موجود در `.nvmrc` و کامپایلر C نیاز دارید. جزئیات بیشتر در [راهنمای مشارکت](CONTRIBUTING.md) و [راهنمای فرانت‌اند](frontend/README.md) آمده است.

نمونه راه‌اندازی محلی:

```bash
cp .env.example .env
cd frontend
npm ci
npm run build
cd ..
go run .
```

ساخت اولیه فرانت‌اند برای قرار گرفتن فایل‌های آن در برنامه Go لازم است. در اولین اجرا، اطلاعات ورود تولیدشده را در ترمینال ببینید. برای توسعه فرانت‌اند با بارگذاری خودکار، پنل Go را روشن نگه دارید و در پوشه `frontend` دستور `npm run dev` را اجرا کنید؛ Vite در `http://localhost:5173` در دسترس است و درخواست‌ها را به پنل روی پورت `2053` می‌فرستد. قابلیت‌های Xray همچنین به فایل اجرایی و داده‌های Xray در مسیر پیکربندی‌شده نیاز دارند.

برای بررسی تغییرات:

```bash
cd frontend && npm test && npm run typecheck
# از ریشه مخزن:
go test ./...
```

## ساخت نسخه قابل نصب

[گردش‌کار Release](.github/workflows/release.yml) بسته‌های معماری‌ها و فایل checksum را می‌سازد. برای ساخت محلی روی لینوکس با Docker buildx:

```bash
bash scripts/build-native-release.sh amd64
bash scripts/build-native-release.sh arm64
```

هر فایل فشرده را همراه فایل `.sha256` آن در Release تگی منتشر کنید که به همان commit کد اشاره می‌کند. ساخت تگ به‌تنهایی کافی نیست و فایل مناسب معماری باید به Release پیوست شود. ساخت برای معماری دیگر به محیط buildx سازگار نیاز دارد.
